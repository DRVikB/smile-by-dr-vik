## Repairs shipped

- Resolved mixed design goals into explicit FDI tooth groups. A shade-only tooth no longer receives an unscoped repair/reshape instruction intended for a neighbour. Texture and material instructions are also subordinate to the individual goal.
- Retained conservative edge-length rules, both-arch protection, unchanged gums and bite relationship, clinician restrictions, and conditional lip-arc guidance. Aesthetic presets and reference images cannot expand the requested edit permissions.
- Added temporary supported-aspect-ratio request canvases for cropped photographs. Known borders are removed on return; the stored original is unchanged. Unexpected output framing is still rejected. This corrects a transport/alignment problem, not AI-invented dental geometry.
- Invalid image dimensions and out-of-frame guide/source regions fail before a provider call.
- Fixed OpenAI silently ignoring attached references. It now sends the requested reference and up to three own-case images in the stated order. Gemini already did this. The actual configured OpenAI model now participates in cache identity. No provider or model was switched.
- New cases, demos and validation cases clear previous identity, clinical context and reference pins. Delayed image preparation cannot repopulate a closed case.
- Saved cases retain clinician review notes and size flags for later exports. Updating a review cannot resurrect a deleted case. Storage/deletion failures provide feedback.
- Fixed pinch/cancel gestures being interpreted as double taps in the camera. Front-camera mirroring and rear-camera default remain.
- Added touch-friendly positive/negative controls for clinical measurements, preserving the distinction between blank and zero.
- Fixed clipped review-drawer scrolling in short landscape layouts. Removed an original-photo label that showed through the collapsed touch panel.
- Fixed error-banner animation moving its dismiss button off the screen. Storage notices remain visible over immersive screens.
- Cleared stale analysis export data when the image changes. Sharing failures remain visible; repeated share taps are disabled during handoff.
- Changed treatment-note wording so low intensity describes an intention rather than claiming the result was verified as conservative.

## Remaining limits and next priorities

### Clinical outcome validation

Passing software tests does not validate an achievable treatment outcome. The current model can still alter teeth or gums contrary to its instructions. Face protection restores pixels outside the lip region; it is not tooth segmentation. A clinician-painted edit region protects its exterior, but changes inside it still require review.

A single photograph does not establish occlusal contacts, restorative clearance, preparation requirements or exact material/shade optics. Added clinical data constrains the instruction; it does not turn the app into a calibrated 3D treatment-planning system. Assess “best” against a held-out set of the clinician's actual paired before/after cases, scored for edge length, untreated anatomy, gum preservation, material appearance and treatment feasibility. Keep those outcomes out of generation references during evaluation.

### Wider clinic access and budget protection

The public generation endpoint rejects duplicate request IDs and cross-origin browser requests, but has no clinician authentication or account-level spend cap. Its case allowance is client-side. Before broader clinic/public distribution, add appropriate access control and server-enforced usage/spend limits. Duplicate prevention is not protection against deliberately minted requests.

### Physical iOS checks

WebKit device emulation is not an actual iPhone/iPad Home Screen installation. Final checks on physical devices should cover status bars/rotation, camera permission and hardware switching, HEIC selection, and native video/file sharing. No claim of complete native-device or accessibility certification is made.

### Cost

The fixes add no extra analysis-model pass or automatic regeneration. Request padding is local. OpenAI now sends references it previously ignored, so enabling those references adds their intended image-input cost; it still uses one generation call. The live Gemini receipt is a test estimate, not a billing invoice or a guaranteed price for every case.

## Follow-up: uncropped uploaded photographs

All primary patient-photo views now contain the complete source image, centred at its original aspect ratio, over a blurred decorative copy. This covers upload, design, before/after, consultation, saved comparison and the generation splash. Removed the fill/crop toggle; intentional pinch zoom remains, with a touch-accessible “Show whole photo” reset. The generation splash animates its backdrop only. Provider canvas padding still uses a neutral border, which is removed from the returned preview; source pixels are never cropped to satisfy an aspect ratio. Wide/tall source dimensions are accepted by canvas preparation.
